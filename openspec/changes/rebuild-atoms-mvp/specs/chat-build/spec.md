# Spec Delta

## Purpose

定义项目对话式构建能力：用户在项目对话页以自然语言提出需求，系统调用单一 LLM 流式生成回复并持久化对话历史，支撑多轮迭代。

## ADDED Requirements

### Requirement: 对话消息流
项目对话页 MUST 展示该项目的历史消息流与输入框。用户发送的消息 MUST 立即出现在消息流中。

#### Scenario: 打开项目对话
- **WHEN** 用户从项目列表进入某项目
- **THEN** 显示该项目的消息流与输入框，光标聚焦输入框

### Requirement: 流式生成回复
用户发送消息后，系统 MUST 调用 LLM 并以流式方式逐块渲染回复。生成完成前，输入 MUST 可用但系统 MUST 呈现进行中状态。

#### Scenario: 流式接收回复
- **WHEN** 用户发送一条需求消息
- **THEN** 回复内容以增量方式逐步出现在界面上，期间显示生成中状态

#### Scenario: 生成期间追加消息
- **WHEN** 用户在生成进行中再次发送消息
- **THEN** 新消息排队并在当前生成完成后处理

### Requirement: 多轮迭代
生成完成后用户 MUST 能继续发送修改需求，系统 MUST 结合项目已有上下文生成后续回复。

#### Scenario: 迭代修改需求
- **WHEN** 用户在收到首次回复后发送修改需求
- **THEN** 新回复体现对先前内容与修改要求的结合

### Requirement: 对话历史持久化
对话消息 MUST 持久化到服务端。用户刷新或重新进入项目对话页后 MUST 能看到完整历史。

#### Scenario: 刷新后恢复历史
- **WHEN** 用户刷新对话页或从列表重新进入项目
- **THEN** 历史消息按原顺序完整呈现

### Requirement: 生成失败处理
模型调用失败时 MUST 显示错误与重试入口，用户已输入的未成功处理的消息 MUST NOT 丢失。

#### Scenario: 生成失败可重试
- **WHEN** 模型调用失败
- **THEN** 界面显示错误提示与重试按钮，重试成功后正常追加回复
