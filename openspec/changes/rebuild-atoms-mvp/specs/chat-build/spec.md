# Spec Delta

## Purpose

定义构建对话控制面：`/chat/{id}` 承载项目消息流，用户消息触发应用构建任务，构建过程流式反馈，历史持久化且失败可重试。生成什么产物由 `app-generation` 规格定义。

## ADDED Requirements

### Requirement: 对话消息流
项目对话页 MUST 展示该项目的历史消息流与输入框。用户发送的消息 MUST 立即出现在消息流中。

#### Scenario: 打开项目对话
- **WHEN** 用户从项目列表进入某项目
- **THEN** 显示该项目的消息流与输入框，光标聚焦输入框

### Requirement: 消息触发构建
用户发送消息后，系统 MUST 为该项目启动构建任务，并在消息流中呈现该轮构建的过程与完成结果。构建进行中再次发送的消息 MUST 排队并在当前构建完成后处理。

#### Scenario: 发送需求触发构建
- **WHEN** 用户在对话中发送一条需求消息
- **THEN** 消息立即出现在消息流中，项目进入构建中状态，完成后消息流中呈现本轮结果

#### Scenario: 构建期间追加消息
- **WHEN** 用户在构建进行中再次发送消息
- **THEN** 新消息排队并在当前构建完成后处理

### Requirement: 构建过程流式反馈
构建任务的过程输出 MUST 以流式方式逐块呈现在对话界面，构建完成前 MUST 显示进行中状态。

#### Scenario: 流式接收过程输出
- **WHEN** 构建任务运行中
- **THEN** 过程内容以增量方式逐步出现在界面上，期间显示构建中状态

### Requirement: 多轮迭代对话
构建完成后用户 MUST 能继续发送修改需求，系统 MUST 结合项目上下文与当前产物处理后续轮次。

#### Scenario: 迭代修改需求
- **WHEN** 用户在某轮构建完成后发送修改需求
- **THEN** 系统基于项目上下文与当前产物处理该需求并再次反馈构建结果

### Requirement: 对话历史持久化
对话消息 MUST 持久化到服务端。用户刷新或重新进入项目对话页后 MUST 能看到完整历史。

#### Scenario: 刷新后恢复历史
- **WHEN** 用户刷新对话页或从列表重新进入项目
- **THEN** 历史消息按原顺序完整呈现

### Requirement: 构建失败处理
构建任务失败时 MUST 显示错误与重试入口，用户已发送的消息 MUST NOT 丢失，当前项目产物 MUST 保持失败前版本。

#### Scenario: 构建失败可重试
- **WHEN** 构建任务失败
- **THEN** 界面显示错误提示与重试按钮，重试成功后正常追加结果
