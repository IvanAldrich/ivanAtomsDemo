# Spec Delta

## Purpose

定义工程构建编排能力：把 agent 生成的代码工程在受控沙箱中变成可运行产物，用错误回传驱动的自动修复循环逼近「一次描述即可用」，并以资源与轮次约束保护平台。

## ADDED Requirements

### Requirement: 沙箱构建
构建 MUST 在与宿主平台隔离的沙箱环境中执行依赖安装与构建。沙箱 MUST 施加资源约束（单次构建时长、内存/磁盘上限），且构建过程 MUST NOT 访问宿主平台的数据与会话。可用隔离级别（容器/受限进程）MUST 可配置并在界面与日志中明示当前级别。

#### Scenario: 构建在沙箱中执行
- **WHEN** 触发某项目的构建
- **THEN** 依赖安装与构建在隔离环境中执行，宿主平台的业务数据不可被构建过程访问

#### Scenario: 隔离级别明示
- **WHEN** 平台以降级隔离级别运行（无容器环境时）
- **THEN** 界面与构建日志明示当前隔离级别及其非生产级性质

### Requirement: 构建日志可观测
构建过程中的安装与构建输出 MUST 实时回传到项目对话（流式），用户 MUST 能看到失败原因原文（可截断）。

#### Scenario: 构建日志流式呈现
- **WHEN** 构建任务运行中
- **THEN** 依赖安装与构建日志逐块出现在对话界面

### Requirement: 自修复循环
构建或启动验证失败时，系统 MUST 把错误信息（截断摘要）回传给生成方产出修复版工程并重新构建，循环执行直至成功或达到轮次上限。达到上限 MUST 明确报告失败并保留项目当前版本不变。

#### Scenario: 失败自动修复成功
- **WHEN** 某轮工程构建失败
- **THEN** 错误信息回传生成方，修复版工程重新构建直至成功，全过程在对话中可见

#### Scenario: 达到修复轮次上限
- **WHEN** 连续多轮修复仍失败并达到上限
- **THEN** 系统明确报告失败原因，项目当前版本与运行状态保持不变

### Requirement: 启动验证
构建成功后系统 MUST 执行启动验证（按约定命令启动并探测端口就绪），验证通过才判定该轮构建成功。

#### Scenario: 启动验证通过
- **WHEN** 构建产物按约定命令启动且端口就绪
- **THEN** 该轮构建判定成功并产出可交付的运行产物

#### Scenario: 启动失败进入修复
- **WHEN** 构建成功但启动验证失败
- **THEN** 失败信息进入自修复循环处理

### Requirement: 构建资源与并发约束
系统 MUST 限制同时执行的构建数量（并发上限）与单次构建资源，单机资源不足时构建 MUST 排队而非并行堆积。

#### Scenario: 并发受限排队
- **WHEN** 两个项目同时触发构建而并发上限为 1
- **THEN** 第二个项目排队等待，第一个完成后再执行

### Requirement: 工程删除级联
删除项目时 MUST 终止其运行时并清理工程快照、构建产物与运行数据。

#### Scenario: 删除清理
- **WHEN** 用户删除某项目并确认
- **THEN** 其运行进程/容器终止，磁盘上的工程与数据目录被移除
