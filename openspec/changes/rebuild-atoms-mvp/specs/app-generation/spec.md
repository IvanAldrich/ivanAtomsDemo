# Spec Delta

## Purpose

定义应用产物生成能力：从自然语言需求生成自包含、可直接运行的单页 Web 应用，产物按版本演进、失败受保护、在沙箱中渲染——用户的产品由此产生。

## ADDED Requirements

### Requirement: 生成自包含可运行应用
项目收到首条需求消息后，系统 MUST 调用 LLM 生成一个完整、自包含的单页 Web 应用产物（HTML/CSS/JS，浏览器打开即可运行，不依赖宿主服务端运行时），并保存为该项目的产物。

#### Scenario: 首次需求产出可运行应用
- **WHEN** 项目处理第一条需求消息并构建成功
- **THEN** 项目拥有一个应用产物，在浏览器中打开即可完整交互

#### Scenario: 产物自包含
- **WHEN** 在无宿主服务的情况下加载项目产物
- **THEN** 产物页面样式与交互功能正常

### Requirement: 产物版本化
每次成功构建 MUST 保存为新的产物版本，并关联触发它的消息。项目 MUST 始终有一个「当前版本」= 最近一次成功构建的产物。

#### Scenario: 多轮迭代后当前版本正确
- **WHEN** 项目经历三轮成功构建
- **THEN** 项目当前版本为第三轮产物，且每个版本可追溯到其触发消息

### Requirement: 基于上下文的迭代更新
后续需求构建 MUST 结合项目需求历史与当前产物生成更新版本；成功后项目当前版本 MUST 更新为新产物。

#### Scenario: 迭代体现在产物中
- **WHEN** 用户要求修改当前应用的某处并构建成功
- **THEN** 新版本产物体现该修改，旧版本仍被保留

### Requirement: 生成失败保护
构建失败时项目当前版本 MUST 保持不变，界面 MUST 提供重试入口。

#### Scenario: 失败保留旧版本
- **WHEN** 某轮构建失败
- **THEN** 项目当前版本仍为上一轮成功产物，重试入口可用

### Requirement: 产物沙箱渲染
应用产物 MUST 在与宿主应用隔离的沙箱上下文中渲染：产物内脚本 MUST NOT 获取宿主会话、Cookie 或同源权限。

#### Scenario: 产物无法访问宿主
- **WHEN** 产物内脚本尝试读取宿主 Cookie 或父页面数据
- **THEN** 沙箱阻止该访问且宿主会话不受影响
