# Spec Delta

## Purpose

定义全栈工程生成能力：agent 从自然语言需求自由设计并产出多文件 Node/npm 代码工程（前端、后端、数据持久化），工程以构建成功为界形成版本，随对话迭代演进——用户的产品的源代码由此产生。

## ADDED Requirements

### Requirement: 自由生成完整全栈工程
项目收到首条需求消息后，系统 MUST 调用 LLM 自由生成一个多文件的 Node/npm 全栈代码工程：MUST 包含前端界面、后端服务与数据持久化实现，MUST 包含使工程可构建运行的完整定义（依赖声明与启动命令）。系统 MUST NOT 限定工程的框架、目录结构或依赖选型（自由生成）。

#### Scenario: 首次需求产出全栈工程
- **WHEN** 项目处理第一条需求消息（如「做一个带用户登录的待办应用」）
- **THEN** 生成的工程包含前端页面、后端接口与数据持久化实现，且具备可进入构建管线的完整定义

### Requirement: 工程文件协议落盘
生成过程 MUST 以明确的文件协议输出（每个文件以路径与内容标识），系统 MUST 按协议将工程落盘为完整的目录快照，并 MUST 校验协议完整性（路径合法、无缺失声明）。

#### Scenario: 多文件正确落盘
- **WHEN** 一轮生成完成
- **THEN** 工程目录包含协议声明的全部文件，路径与内容一致

### Requirement: 基于上下文的迭代修改
后续需求构建 MUST 结合需求历史与当前工程生成修改：MUST 支持新增、修改与删除文件，未提及的文件 MUST 保持不变。

#### Scenario: 迭代修改反映在工程中
- **WHEN** 用户要求给现有应用增加一个页面并生成成功
- **THEN** 新工程包含该页面相关文件，其余文件与上一版本一致

### Requirement: 以构建成功为界的版本化
每轮生成 MUST 产出候选工程快照；仅当该快照通过构建管线验证（构建并可启动）时，MUST 将其保存为新的工程版本并关联触发的消息。项目当前版本 MUST 为最近一次通过构建验证的版本。

#### Scenario: 版本以构建成功为界
- **WHEN** 某轮生成经构建验证失败且自修复未成功
- **THEN** 不产生新版本，项目当前版本保持不变

#### Scenario: 版本可追溯
- **WHEN** 项目经历多次成功迭代
- **THEN** 每个版本可追溯到触发它的消息，当前版本为最近成功版本

### Requirement: 生成内容安全约束
生成的工程 MUST 遵守平台约定的运行契约：监听指定端口环境变量、不访问宿主平台的数据与会话、持久化数据写入工程自身目录。系统 MUST 在生成提示中注入这些约束并拒绝明显违反契约的产物进入构建。

#### Scenario: 运行契约注入
- **WHEN** 生成请求组装提示词
- **THEN** 提示词包含端口约定、数据目录约定与宿主隔离约束
